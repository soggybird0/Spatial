Spatial

A shared spatial hitbox library for Roblox. Works on server and client. Handles latency, prediction, lag compensation, velocity, and exploits — so you don’t have to fight .Touched.

v1.0.1 Server + Client Lag Compensation Luau Strict MIT License
API Reference Examples GitHub

Features

Shared Server + Client

Predictive hits on the client, authoritative confirmation on the server.

Lag Compensation

Server rewinds target poses to the claim timestamp before validating.

Velocity Prediction

Accounts for moving targets instead of static snapshots.

Flexible Shapes

Box, Sphere, or Part-based hitboxes with origin + offset welding.

Authority Modes

Server, Client, or Hybrid — pick the right tradeoff per attack.

Budget-Aware

Hard limits on queries per frame and claim rate per player.

Fail-Closed

Explicit reject reasons. Nothing is accepted by default.

Type-Safe

Full Luau types for params, results, and enums.

Installation

[dependencies]
Spatial = "soggybird0/spatial@1.0.1"
-- Place under ReplicatedStorage, require from both sides
local Spatial = require(ReplicatedStorage.Spatial)

Quick Start

Require Spatial once on the server so remotes and pose history exist before any client talks.

Server (authoritative damage)

local Server = require(ReplicatedStorage.Spatial).Server

local hitbox = Server:Create({
    Shape = "Box",
    Size = Vector3.new(6, 6, 8),
    Origin = character.HumanoidRootPart,
    Offset = CFrame.new(0, 0, -4),
    Duration = 0.25,
    Authority = "Hybrid",
    Owner = player,
})

hitbox.Hit:Connect(function(result)
    if result.Humanoid then
        result.Humanoid:TakeDamage(25)
    end
end)

hitbox:Start()

Client (predictive VFX only)

local Client = require(ReplicatedStorage.Spatial).Client

local hitbox = Client:Create({
    Shape = "Sphere",
    Radius = 5,
    Origin = character.HumanoidRootPart,
    Duration = 0.2,
})

hitbox.Hit:Connect(function(result)
    playHitEffect(result.Position) -- never apply damage here
end)

hitbox:Start()
Rule of thumb Apply damage and gameplay effects only from Spatial.Server.Hit. Use Spatial.Client.Hit for instant visual/audio feedback.

Architecture

Spatial is built around one rule: clients may predict; only the server may decide.

  1. Client runs spatial queries and fires a claim (hitbox ID, timestamp, victim tokens).
  2. Server rate-limits, looks up the hitbox, rewinds tracked poses to the claim time.
  3. Server re-tests intersection against the rewound world.
  4. Emits confirmed Hit or Rejected with an explicit reason.

Gameplay logic should only listen to the server Hit signal.

Pose history Track every potential target with Server.Track(model) so lag compensation can rewind them. Owner characters are tracked automatically when you pass Owner.

Configuration

Override defaults early with Configure:

Server:Configure({
    MaxRewind = 0.5,
    QueriesPerFrame = 48,
    ClaimRate = 18,
    Debug = false,
})

Tracking & Rewind

Players.PlayerAdded:Connect(function(player)
    player.CharacterAdded:Connect(function(character)
        Server:Track(character)
    end)
end)

-- NPCs
Server:Track(npcModel)
Server:Untrack(npcModel) -- on despawn

Debug

Server.DebugHook:SetEnabled(true)
print(Server:Metrics())
print(Server:Health())

Client.DebugHook:SetEnabled(true)

When debug is on, Spatial draws temporary markers at query volumes and hit positions in Studio.
